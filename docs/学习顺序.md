# 学习顺序

项目一共 30 多个文件，一次读会迷路。这里按**依赖关系**排了个顺序：每个文件只依赖前面读过的内容，读的时候不会遇到"这个函数从哪来的"。

## 先看这张图

```
HTTP 请求
   ↓
api/v1/qa.py          ← 第 4 站
   ↓
core/orchestrator.py  ← 第 3 站（编排层）
   ↓
agents/qa/graph.py    ← 第 2 站（图结构）
   ↓
agents/qa/nodes.py    ← 第 2 站（7 个节点）
   ├─ cache.py         ← 第 5 站（Redis 答案缓存）
   ├─ faq.py           ← 第 6 站（Postgres + BM25）
   └─ retrieval/       ← 第 7 站（Milvus 向量检索）
```

**先读图，再读节点，最后读节点调用的能力模块。** 反过来读会一直不知道"这个节点为什么需要这个参数"。

---

## 第 1 站：项目怎么跑起来（30 分钟）

| 顺序 | 文件 | 关注点 |
|---|---|---|
| 1 | `README.md` | 项目定位、启动命令 |
| 2 | `docker-compose.yml` | 四个容器：postgres / etcd / minio / milvus，端口为什么是 5434、19532 |
| 3 | `requirements.txt` | 依赖分四组；torch 为什么要单独装 |
| 4 | `config.py` | **唯一配置中心**，39 个字段；`get_settings()` 为什么用 `lru_cache` |
| 5 | `.env`（不在仓库里） | 配置的真实值；`.env` 与 `config.py` 默认值谁优先 |

**自测**：不看代码，说出 `milvus_port` 的值从哪来、改哪个文件生效。

## 第 2 站：工程内核（1 小时）

这一层所有 Agent 都会用到，先读懂后面才不卡。

| 顺序 | 文件 | 关注点 |
|---|---|---|
| 6 | `core/logger.py` | structlog 封装；为什么用 `event + kwargs` 而不是 `f"..."` |
| 7 | `core/exceptions.py` | 异常分「可重试 / 不可重试」两组，谁在用这个分类 |
| 8 | `core/retry.py` | 三层兜底：重试 → 降级 → 系统兜底；超时为什么是 150s |
| 9 | `core/llm_factory.py` | 唯一模型入口；`trust_env=False` 解决什么 |

**自测**：一个节点抛 `ConnectionError`，会被重试几次？抛 `InvalidInputError` 呢？

## 第 3 站：问答 Agent（2 小时）

### 3.1 先看数据结构与图

| 顺序 | 文件 | 关注点 |
|---|---|---|
| 10 | `agents/qa/state.py` | `QAState` 每个字段谁写谁读；`add_messages` reducer |
| 11 | `agents/qa/graph.py` | **只有 80 行，先把图画出来**：cache → classify → faq / strategy → retrieve → generate |

### 3.2 再按图的顺序读节点

| 顺序 | 函数（都在 `nodes.py`） | 关注点 |
|---|---|---|
| 12 | `cache_lookup_node` | 命中就直接 END，连分类都不做 |
| 13 | `classify_node` | 通用知识 vs 专业咨询；为什么失败时默认"专业" |
| 14 | `faq_node` | FAQ 命中就出答案，不走模型 |
| 15 | `strategy_node` | 4 种检索策略怎么选 |
| 16 | `retrieve_node` | 调向量库；`source` 过滤从哪来 |
| 17 | `generate_node` | 拼 context + 调模型；`_stream_or_invoke` 怎么实现流式 |
| 18 | `cache_write_node` | 为什么缓存命中的轮次不再写 |

### 3.3 再看提示词

| 顺序 | 文件 | 关注点 |
|---|---|---|
| 19 | `agents/qa/prompts.py` | 分类提示词里为什么要列"知识库覆盖哪些主题" |

**自测**：为什么 `Docker Compose 怎么部署` 必须判成专业咨询？提示词的哪一句在起作用？

## 动手验证顺序（和阅读交替进行）

```powershell
# 1. 起基础设施
cd D:\AI实战\Myagent
docker compose up -d

# 2. 灌知识库（会看到五种格式各自的解析结果）
python -m scripts.ingest --reset
python -m scripts.ingest --query "你们怎么收费"

# 3. 灌 FAQ（会看到 BM25 命中分数）
python -m scripts.ingest_faq
python -m scripts.ingest_faq --query "你们怎么收费"

# 4. 起服务
uvicorn main:app --reload --port 8000

# 5. 三个入口都试一遍
#    http://127.0.0.1:8000/          前端
#    http://127.0.0.1:8000/docs      接口文档
#    http://127.0.0.1:8000/health    健康检查
```

## 建议的节奏

| 天 | 内容 | 产出 |
|---|---|---|
| 1 | 第 1-2 站 | 能说清配置从哪来、重试怎么兜底 |
| 2 | 第 3 站 | 能画完整的图，说清每个节点干什么 |
| 3 | 4.1 + 4.2 | 能解释缓存失效与 FAQ 命中 |
| 4 | 4.3 | 能解释向量入库与检索全流程 |
| 5 | 第 5 站 | 能自己加一个新接口 |

**不要按文件名字母序读**（`agents` → `api` → `core` → `scripts`），那样会先读到调用方、后读到被调用方，越读越困惑。
