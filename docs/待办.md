### 联网检索状态区分（2026-10-22 修复）

原来 `Tavily 挂了 / 被限流 / 没配 key / 确实没搜到` 全被吞成空列表，统一回复
"没有找到足够的公开资料"——用户会把服务故障理解成知识库缺失。

现在有独立的结果类型 `SearchOutcome(status, items, detail)`：

| 状态 | 触发 | 给用户的提示 |
|---|---|---|
| `ok` | 拿到资料 | （正常作答） |
| `no_result` | 服务正常但没搜到 | 公开资料中没有找到相关内容 |
| `rate_limited` | 429 / 限流 | 服务被限流，请稍后再试 |
| `no_key` | 没配搜索密钥 | 没配置检索密钥，请联系管理员 |
| `failed` | 网络、MCP 异常等 | 联网检索服务暂时不可用，请稍后重试 |

实测（手动停掉 MCP 服务）：
```
知识库中没找到与这个问题相关的内容。

联网检索服务暂时不可用，请稍后重试。
```
`/api/v1/ask` 的 `web_status`、`/api/v1/research/ask` 的 `search_status` 都会带上状态，
恢复后同问题返回 `ok`。

顺带把 MCP 客户端从 `nodes.py` 拆到 `mcp_client.py`，解开 `nodes ↔ collector` 的循环依赖。

## 已知问题

### 1. `qa` 首字延迟偏高（约 8~9 秒）

**现象**：qa 路径从发请求到第一个字要 8~9 秒，而 research 只要 5.5 秒。

**原因**：qa 在生成前要串行做两件事——意图分类（LLM 调用）+ 检索策略选择（又一次 LLM 调用），
再叠加嵌入与精排。research 的规划与搜索是并发的。

**可选修法**：
- 分类与策略选择合并成一次结构化输出（省一次往返）
- 策略选择加缓存（同问题第二次直接命中）
- 简单问题直接跳过策略选择，默认「直接检索」

**影响**：体验问题，不影响正确性。
