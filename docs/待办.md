### 联网检索状态区分（2026-10-22 修复）

原来 `Tavily 挂了 / 被限流 / 没配 key / 确实没搜到` 全被吞成空列表，统一回复
"没有找到足够的公开资料"——用户会把服务故障理解成知识库缺失。

现在有独立的结果类型 `SearchOutcome(status, items, detail)`：

| 状态 | 触发 | 给用户的提示 |
|---|---|---|
| `ok` | 拿到资料 | （正常作答） |
| `no_result` | 服务正常但没搜到 | 公开资料中没有找到相关内容 |
| `rate_limited` | 429 / 限流 | 服务被限流，请稍后再试 |
| `no_key` | 没配搜索密钥 | 没配置检索密钥，请联系管理员 |
| `failed` | 网络、MCP 异常等 | 联网检索服务暂时不可用，请稍后重试 |

实测（手动停掉 MCP 服务）：
```
知识库中没找到与这个问题相关的内容。

联网检索服务暂时不可用，请稍后重试。
```
`/api/v1/ask` 的 `web_status`、`/api/v1/research/ask` 的 `search_status` 都会带上状态，
恢复后同问题返回 `ok`。

顺带把 MCP 客户端从 `nodes.py` 拆到 `mcp_client.py`，解开 `nodes ↔ collector` 的循环依赖。

## 已知问题

### 1. `qa` 首字延迟偏高（约 8~9 秒）

**现象**：qa 路径从发请求到第一个字要 8~9 秒，而 research 只要 5.5 秒。

**原因**：qa 在生成前要串行做两件事——意图分类（LLM 调用）+ 检索策略选择（又一次 LLM 调用），
再叠加嵌入与精排。research 的规划与搜索是并发的。

**可选修法**：
- 分类与策略选择合并成一次结构化输出（省一次往返）
- 策略选择加缓存（同问题第二次直接命中）
- 简单问题直接跳过策略选择，默认「直接检索」

**影响**：体验问题，不影响正确性。

## 已完成（续）

### 联网答案缓存（2026-10-22）

qa 与 research 共用同一个 `AnswerCache`，靠**命名空间**区分，而不是各写一套：

```
qa:ans:v{ver}:s{scope_hash}:{query_hash}              ← 知识库答案，TTL 24h
qa:ans:research:v{ver}:s{scope_hash}:{query_hash}     ← 联网答案，TTL 6h
```

设计要点：
- **不把缓存做成 MCP**：缓存查询在热路径上，走 MCP 会多一次网络往返 + 多一个故障点，
  反而抵消了缓存的意义。MCP 的语义是"模型决定调哪个工具"，缓存是基础设施。
- 联网 TTL 更短（6h）：公网信息会变，缓存一天容易答过时内容
- 只缓存 `answer_mode=web` 的成功结果：没搜到 / 搜失败不写缓存，
  否则一次服务故障会被缓存扩散成几小时的误报
- 权限范围仍然进键：不同部门/角色不共享

实测：同一问题第一次 11.2s（走 MCP + 生成），第二次 **0.02s**，加速 650 倍。

## 已完成（续）

### deep 模式：让模型自主打开网页正文（2026-10-22）

`fetch_page` 之前是死代码（暴露了但没人调用），现在接上了：

```
POST /api/v1/research/ask  {"depth": "fast" | "deep"}
POST /api/v1/ask           {"depth": "fast" | "deep"}   （路由到 research 时生效）
```

控制流（`_synthesize_deep`）：
1. 第 1 轮用 `tool_choice="required"` **强制**调一次 `fetch_page`
   —— 用户既然选了 deep，就该真读原文，不能因为摘要看起来够了就跳过
   （实测提示语写"需要时再读"，模型永远判断"不需要"）
2. 之后由模型自主决定是否继续读，上限 `RESEARCH_MAX_PAGE_FETCHES=2`
3. 收尾不带工具再问一次，确保输出的是文本答案而不是工具调用

同时修了正文提取质量问题：原来 `fetch_page` 返回的前 300 字全是导航菜单。
现在是：先取 `<article>`/`<main>` → 从第一个 `<h1>` 开始切 → 去噪标签 → 块级标签转换行。
实测同一页面从"导航菜单"变成"HNSW 是一种基于图的索引算法…"。

实测对比（问题：HNSW 的 M 参数默认值和范围）：
```
fast  11.1s / 459 字 / 只用摘要
deep  36.5s / 641 字 / 读了 2 页正文，能指出资料间的数值矛盾
```

**代价**：deep 明显慢（每页 1~3 秒 + 多轮往返），所以默认仍是 fast。
