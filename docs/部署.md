# 部署指南

三条路径，按"别人怎么用你的程序"选一条。

---

## 一、最快：局域网共享（5 分钟）

你的机器已经把服务跑在 `0.0.0.0:8000`，同一网络的人直接访问：

```powershell
# 1. 查你的内网 IP
ipconfig | findstr IPv4        # 例如 192.168.1.10
```

对方浏览器打开：`http://192.168.1.10:8000/`

注意事项：

- Windows 防火墙首次会弹窗，选「允许访问」
- 数据库、模型都跑在你机器上：你关机，对方就断
- 对方用的是**你的**账号体系，不是独立环境

## 二、推荐：对方独立部署（Docker）

### 前置条件

| 项 | 要求 |
|---|---|
| Docker Desktop | Windows 10+ / macOS 均可 |
| 磁盘 | 约 12 GB（镜像 3.5 GB + 模型 4.3 GB + 数据） |
| 模型权重 | BGE-M3 与 bge-reranker-large，约 4.3 GB，**不在仓库里**，需单独传（网盘 / U 盘） |
| API Key | DeepSeek（必填）、Tavily（要联网研究则必填） |

### 步骤

```bash
# 1. 拉代码
git clone https://github.com/5G555/agent-workbench.git
cd agent-workbench

# 2. 准备配置：复制模板后改三个必填项
cp .env.example .env          # Windows: copy .env.example .env
#   DB_PASSWORD=你的数据库密码
#   JWT_SECRET_KEY=随机长字符串
#   DEEPSEEK_API_KEY=sk-...
#   TAVILY_API_KEY=tvly-...   （可选，没有则联网研究不可用）
```

模型权重放好，例如 `D:/AI-Models/` 下：

```
D:/AI-Models/
├── embedding/bge-m3/
├── reranker/bge-reranker-large/
└── classifier/intent_router_ft/
```

然后在 `docker-compose.yml` 里把挂载路径改成你的实际路径：

```yaml
  app:
    volumes:
      - D:/AI-Models:/models:ro          # ← 改成你的模型目录
```

```bash
# 3. 起服务（首次会构建镜像，约 5~10 分钟）
docker compose --profile app up -d

# 4. 建表
docker compose exec app alembic upgrade head

# 5. 创建第一个管理员（密码只显示一次，记下来）
docker compose exec app python -m scripts.init_admin --username admin
```

打开 `http://localhost:8000`，用上一步的用户名密码登录。

### 首次使用还要做什么

空库里没有知识，FAQ 与文档都要灌进去，否则问答只会走联网：

```bash
# 导入 FAQ（Excel/CSV 按 scripts/ingest_faq.py 的参数）
docker compose exec app python -m scripts.ingest_faq --help

# 导入文档（PDF/Word 等，需要先转文本或直接用脚本支持的类型）
docker compose exec app python -m scripts.ingest --help
```

### 构建慢 / 拉不到依赖怎么办

Dockerfile 默认走官方源（`pypi.org`、`download.pytorch.org`）。国内可直接换源：

```bash
docker compose build --build-arg PIP_INDEX=https://pypi.tuna.tsinghua.edu.cn/simple app
```

## 三、公网访问（谨慎）

| 方式 | 命令 / 做法 | 风险 |
|---|---|---|
| 内网穿透 | `cloudflared tunnel --url http://localhost:8000` | 域名公开后任何人可访问，**必须先改默认密码** |
| 云服务器 | 4C8G 起，装 Docker，按「方案二」部署，前面加 Nginx + HTTPS | 每月成本，但最稳 |

公网部署前必须做的三件事：

1. **改掉所有默认账号**（`admin`/`secret123` 这类）
2. **配置 HTTPS**（反代层终止 TLS）
3. **确认 `AUTH_ENABLED=true`**（默认已开）

当前版本没有内置的账号锁定、IP 白名单、审计告警，**不建议直接暴露到公网**。

## 四、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `docker compose up` 后浏览器打不开 | app 容器没起来 | `docker compose ps` 看状态，`logs app` 看报错 |
| 登录提示用户不存在 | 没建管理员 | 执行上面第 5 步 `init_admin` |
| 问答报「没有配置联网检索的密钥」 | 缺 `TAVILY_API_KEY` | 补进 `.env` 后 `docker compose up -d app` |
| 问答报模型加载失败 | 模型路径没挂对 | 检查 `volumes` 与 `BGE_M3_MODEL_PATH` 是否一致 |
| MCP 服务 unhealthy | 健康检查探错端口（镜像自带 /health 是 app 的） | 已在 compose 覆盖，若自定义请保留 `socket` 检查 |
| CI 红 | 本地没跑 ruff/pyright/pytest | `ruf check .` / `pyright` / `python -m pytest -q` |

## 五、升级与备份

```bash
# 升级代码
git pull
docker compose --profile app build app && docker compose --profile app up -d

# 数据库迁移（每次升级后执行）
docker compose exec app alembic upgrade head

# 备份数据库
docker compose exec postgres pg_dump -U myagent myagent > backup.sql
```

数据库、Milvus、Redis 的数据都在 docker volume 里，`docker compose down` **不会**删数据；
`docker compose down -v` 会删——慎用。
