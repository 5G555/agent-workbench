# 提交信息规范

仓库列表里每条提交只显示一列，标题过长会换行、显得杂乱。约定如下。

## 格式

```
<type>: <一句话做了什么>
```

- **type**：`feat` / `fix` / `docs` / `chore` / `refactor` / `test` / `perf`
- **标题 ≤ 40 个字符**，超过就被截断，看不出重点
- **不加 scope 括号**（`feat(analyst):` 这种），省下的字符留给内容
- 需要交代原因、取舍、坑点时，**写在正文**（空一行之后），不要在标题里堆

## 例子

好：

```
feat: 分析结果缓存清理并进运维
fix: 缓存命中时结论显示成问题原文
docs: 每个 Agent 加流程图
chore: 导入路径收敛到两层
```

不好（太长 / 堆了细节）：

```
feat(deploy): 补 .env.example、部署文档、首个管理员创建脚本，并修掉 Dockerfile 与 .dockerignore 的两处遗漏
docs(agents): 每个 Agent 补 README（含 mermaid 流程图），新增多 Agent 协同与跨 Agent 时序图
```

## 正文怎么写

只在必要的时候写，格式：

```
fix: research 空结果不再回「没找到」

判据从"答案含'没有找到'"改成"检索结果为空"——
模型带着来源说没有找到时，那个答案是有依据的，不该被丢弃。

影响：天气类问题现在会落回通用回答，并在末尾说明未引用外部来源。
```

三句话就够：**为什么改 / 怎么改 / 有什么影响**。

## 历史提交

已经推送的提交不改写（`git rebase` + 强推会让别人 clone 冲突）。
从这条规范开始，新提交按上面的来。
